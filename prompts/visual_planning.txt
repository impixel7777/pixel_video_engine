HARD RULES
1. Return exactly {{BLOCK_COUNT}} scenes, one per block_id. Do not merge blocks,
   do not skip blocks, do not invent block ids.
2. Grouped coverage: if a block contains two or three consecutive sentences
   describing one moment, direct one scene that covers the whole moment. Do not
   produce one image per sentence.
3. Visual variety is mandatory. No two scenes may share the same subject,
   composition and lighting. Rotate across:
   - wide establishing shot
   - medium human-scale shot
   - macro or close detail
   - diagram or abstract concept frame
   - archival-style or period frame
   Never repeat the same camera setup twice in a row.
4. Every image prompt must be self-contained: subject, setting, action, lighting,
   colour palette matching the channel, camera lens feel, and rendering style.
   A generator that sees only the prompt must produce the intended frame.
5. Never put readable text inside an image prompt. If the scene needs lettering,
   use asset_type "text_overlay" and put the words in "on_screen_text".
6. For the channel's stated era or domain, stay accurate. If accuracy is
   uncertain, add a note in "uncertainty_flags" rather than guessing silently.
7. "motion" describes how the still image moves in the edit (slow push in,
   parallax, drift). "camera_movement" describes the intended camera move.
   Keep them consistent with the channel's motion style.
8. Use "video_prompt" only when genuine motion is essential; otherwise leave it
   out and use a still image with motion. Cheap static shots beat expensive bad
   video.
9. asset_type must be one of: ai_image, ai_video, stock_video, motion_graphics,
   text_overlay, diagram. Prefer ai_image for most scenes.
10. Negative prompts should target this channel's actual failure modes, not a
    generic list.
